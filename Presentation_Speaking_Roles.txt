[SLIDE 2: Project Overview & Core Philosophy]
• What to say:
  "To understand why we built this, let's look at the core problem with traditional 
   encryption. Traditional encryption converts plaintext into ciphertext. While this 
   protects the confidentiality of the message, the ciphertext itself is completely 
   conspicuous. When transmitted over a network, an attacker using a packet sniffer 
   or a firewall performing Deep Packet Inspection immediately notices high-entropy 
   scrambled data. This flags suspicion, drawing unwanted attention and targeting the 
   channel for surveillance or throttling.
   Our project solves this by introducing a dual-layer defense: first, we encrypt the 
   data using AES-256-GCM; second, we conceal that encrypted data inside ordinary 
   images and audio files using steganography. To any network monitor or eavesdropper, 
   it looks like an ordinary, harmless picture or song being shared, granting complete 
   plausible deniability."

[SLIDE 3: Problem Formulation: Network Threats]
• What to say:
  "Thank you, [Person 1]. In our threat modeling, we focused on four primary network-level 
   vulnerabilities:
   1. Packet Sniffing: Attackers operating tools like Wireshark or tcpdump on shared 
      LANs capture packets in promiscuous mode. Unencrypted files and plaintext messages 
      are captured and reconstructed effortlessly.
   2. IP Snooping & Traffic Analysis: Even if content is encrypted, adversaries monitor 
      IP headers, transmission timestamps, and payload sizes to profile communicating parties.
   3. DPI & Cryptographic Censorship: Firewalls and monitoring nodes actively inspect 
      packet entropy. Obvious ciphertext blobs are often flagged, quarantined, or blocked.
   4. Man-in-the-Middle (MitM) Tampering: Threat actors can alter, truncate, or flip bits 
      in transit. Without integrity controls, a recipient could accept modified data."

[SLIDE 4: System Framework & Operational Pipeline]
• What to say:
  "To address these threats, our system implements an end-to-end 6-step lifecycle:
   - Step 1: The sender inputs their secret message or file, and our real-time entropy 
     engine checks the password strength.
   - Step 2: PBKDF2-HMAC-SHA256 stretches the password across 480,000 iterations with a 
     random 16-byte salt to derive a master 256-bit key.
   - Step 3: The payload and metadata are encrypted using AES-GCM with a fresh 12-byte nonce, 
     generating a 16-byte authentication tag.
   - Step 4: The binary container is embedded into the Least Significant Bits of the chosen 
     image or audio carrier.
   - Step 5: The carrier file is exported strictly losslessly (.png or .wav) and transmitted.
   - Step 6: The recipient extracts the container, validates the cryptographic tag, and 
     restores the original file."

[SLIDE 5: Cryptographic Container Binary Architecture]
• What to say:
  "Thank you, [Person 2]. Before data is embedded into any carrier, it is packed into a 
   rigorous binary container with six fields:
   1. 16-Byte Salt: Generated via os.urandom(16) to eliminate rainbow-table precomputations.
   2. 12-Byte Nonce: Unique initialization vector per encryption to prevent replay attacks.
   3. 2-Byte Filename Length: Big-endian integer specifying metadata size.
   4. N-Byte Original Filename: Encrypted inside the payload so file types are never leaked.
   5. Variable Ciphertext: The AES-256-GCM encrypted payload.
   6. 16-Byte Authentication Tag: The GHASH tag used to verify zero tampering.
   This layout ensures the container is completely self-contained. The receiver only needs 
   the shared password to reconstruct everything."

[SLIDE 6: The Three Core Security Mechanisms (Overview)]
• What to say:
  "To fulfill our evaluation requirements, our architecture strictly enforces THREE 
   independent security mechanisms:
   - Mechanism 1: Authenticated Cryptographic Confidentiality — Powered by AES-256-GCM 
     and high-iteration PBKDF2 key stretching, backed by real-time client-side password 
     strength validation.
   - Mechanism 2: Covert Concealment (Anti-Sniffing) — Implemented via dual-medium LSB 
     steganography in 24-bit images and 16-bit PCM audio, providing plausible deniability.
   - Mechanism 3: Cryptographic Integrity & Tamper Resistance — Enforced by the 16-byte 
     AEAD authentication tag, providing automated detection of any in-transit packet alteration."

[SLIDE 7: Mechanism 1 Deep-Dive: Cryptographic Confidentiality]
• What to say:
  "Thank you, [Person 3]. Under Mechanism 1, we use AES in Galois/Counter Mode (GCM) with 
   a 256-bit key length. A 256-bit key space offers 2^256 possible keys, making brute-force 
   cracking impossible against any modern supercomputer.
   To transform user-supplied passwords into cryptographic keys, we use PBKDF2-HMAC-SHA256 
   with 480,000 iterations. This heavy key stretching intentionally increases the 
   computational cost for an attacker, defeating GPU-accelerated dictionary attacks.
   Furthermore, in our GUI, we developed a real-time Password Strength Meter that 
   actively evaluates character entropy (uppercase, lowercase, numbers, and symbols) as 
   the user types, warning them if a password is too weak to ensure optimal key generation."

[SLIDE 8: Mechanism 2 Deep-Dive: Covert Steganography]
• What to say:
  "Under Mechanism 2, we implement Least Significant Bit (LSB) steganography across two 
   media types:
   - Image Steganography: We load 24-bit RGB images and modify only the 0th bit of each 
     color channel byte. Because this alters pixel luminosity by at most 1 in 256—or 0.39%—the 
     change is completely imperceptible to the human eye.
   - Audio Steganography: We decode audio into 16-bit linear PCM samples. The payload bits 
     replace the least significant bit of the audio samples, producing noise that is entirely 
     beneath the human auditory threshold.
   Crucially, our system enforces lossless output (.png and .wav). Formats like JPEG or MP3 
   use lossy compression that would permanently destroy hidden bits. By using lossless 
   containers, data integrity is preserved 100%."

[SLIDE 9: Mechanism 3 Deep-Dive: Integrity & Tamper Verification]
• What to say:
  "Thank you, [Person 4]. Mechanism 3 addresses active network tampering and Man-in-the-Middle 
   attacks. If an adversary intercepts our stego carrier and tampers with, truncates, or 
   flips even a single bit in the payload, how do we know?
   This is solved by AES-GCM's AEAD property. During encryption, a GHASH polynomial 
   authenticator calculates an immutable 16-byte (128-bit) authentication tag over the 
   ciphertext and nonce.
   When the recipient decodes the carrier, the engine recomputes this tag before releasing 
   any decrypted data. If a single bit was modified in transit, the tags fail to match, 
   raising an immediate InvalidTag exception and aborting decryption. This fail-closed 
   behavior ensures corrupted or malicious payloads are never accepted or executed."

[SLIDE 10: Evaluation Matrix: Threats vs Preventions vs Mechanisms]
• What to say:

   to our preventions and mechanisms:
   1. Packet Sniffing is prevented by Mechanism 2 (LSB Steganography), because Wireshark 
      captures only show harmless media files.
   2. IP Snooping & Traffic Analysis is prevented by Mechanism 2, eliminating suspicious 
      ciphertext signatures.
   3. Unauthorized Data Exposure is prevented by Mechanism 1 (AES-256-GCM + PBKDF2), rendering 
      the payload mathematically unreadable without the secret key.
   4. Man-in-the-Middle Tampering is prevented by Mechanism 3 (16-Byte AEAD Tag), validating 
      authenticity and detecting bit modification."
